# 关键词术语表

本文解释 WordFind 关键词雷达里所有与“词”相关的概念，包括界面用词、数据字段、挖词算法里的判定条件，以及容易混淆的对照关系。

## 1. 三个层级：词 → 组 → 库

| 术语 | 定义 | 例子 | 出现位置 |
| --- | --- | --- | --- |
| 关键词（keyword） | 一个用于 Google Trends 分析的搜索短语，是扩展里的最小单位。 | `running shoes` | 输入框、词库、页面注入、挖词种子 |
| 搜索词 / Query | Google Trends 语境下与“关键词”同义，指用户输入的搜索查询。 | `running shoes` | Trends 接口字段、相关搜索 |
| 关键词组（group） | 一行输入里的多个关键词，最多 5 个；对应一个 Trends 对比页面。 | `running shoes, trail shoes` | 工作台卡片、分析全部 |
| 单个关键词 | 组里的一个词；点击 chip 会单独打开该词的 Trends 页面。 | `trail shoes` | 工作台关键词 chip |
| 词库（library） | 所有关键词的长期存储，一条记录同时承载历史、收藏、词根等状态。 | — | 词库页 |
| 词库记录（record） | 词库里的一条数据：`{keyword, favorite, root, count, firstSeen, lastUsed}`。 | `{keyword:'gpts', favorite:true, root:false, count:3}` | 词库、导出 JSON/CSV |
| 链接组 | TrendsBar 的旧概念：一组用于批量查看的关键词。合并后就是“关键词组”，不再单独存在。 | — | 工作台 |
| 批量查看 | TrendsBar 的旧页签：按分页打开链接组。合并后对应“分析全部”。 | — | 工作台 |

## 2. 挖词链路：种子 → 批次 → 相关词 → 有效新词

| 术语 | 定义 | 例子 / 规则 | 出现位置 |
| --- | --- | --- | --- |
| 种子词（seed） | 自动挖词的起点关键词；后台会把它送进 Trends，读取相关搜索继续扩展。 | `translator`、`processor` | 挖词页种子输入框 |
| 种子队列（queue） | 还没被分析的种子词集合；每批从队首取最多 4 个。 | 队列长度显示在“本轮种子 / 队列”相关状态里 | 挖词状态、后台 |
| 批次（batch） | 一次 Trends 导航里实际分析的关键词集合：1 个基准词 + 最多 4 个种子词，最多 5 个。 | `gpts + translator + processor` | 挖词状态、后台 |
| 对比基准词（benchmark） | 挖词时固定放在每批第一个位置的关键词，用于计算其他词的增长百分比。 | 默认 `gpts` | 挖词页“对比基准词” |
| 对比词 / 对比组 | 手动分析时的参照词；合并后由“第一组关键词”或固定基准词承担，不再单独维护列表。 | 第一组里的 `running shoes` | 工作台、页面注入“对比” |
| 相关词 / 相关搜索（related query） | Google Trends 为某个关键词返回的相关搜索词，优先取 rising 列表，为空时取 top 列表。 | `trail running shoes` | 相关词面板、挖词结果 |
| rising 列表 | Trends 相关搜索里的“搜索量上升”列表，优先作为新词来源。 | — | 后台解析 |
| top 列表 | Trends 相关搜索里的“热门”列表，rising 为空时使用。 | — | 后台解析 |
| 候选词 | 从相关搜索里提取出的新词；通过过滤后才会进入种子队列。 | `trail running` | 后台内部概念 |
| 有效新词（effective new word） | 同时满足三个条件的关键词：时间线前两个点为 0、最后三个点不下降、末点相对基准词达到阈值。 | `ai photo editor`（420%） | 挖词页“有效新词” |
| 有效阈值（threshold） | 有效新词的百分比门槛；默认 20%。 | 末点 55 / 基准末点 10 = 550%，≥20% 通过 | 挖词页“有效阈值 %” |
| 最大词数（max keywords） | 一轮挖词最多处理多少个种子词；默认 200，可设 1–500。 | 达到上限后停止 | 挖词页“最大词数” |
| 已处理（processed） | 已经分析过的种子词数量，按批次累加；不是相关词数量。 | 已处理 24 | 挖词统计 |
| 相关词数 | 本轮发现并记录的相关词总数；包含没有进入队列的词。 | 相关词 8 | 挖词统计 |
| 有效新词数 | 通过有效新词判定的关键词数量。 | 有效新词 2 | 挖词统计 |
| 词根（root） | 本扩展里指“可复用的根词/后缀模板”，不是语言学意义上的词根词缀。内置 50 个英文后缀词，如 Translator、Processor，可导入词库或作为种子。 | `Translator`、`Scraper`、`Optimizer` | 挖词页“内置词根”、词库“词根”标记 |
| 词根词 | 被标记 `root: true` 的词库记录，用于筛选和复用。 | `Translator` | 词库“词根”筛选 |
| 长尾词 | 本扩展没有把它作为独立分类；相关词过滤只限制“不超过 6 个单词”，间接偏向较短查询。 | `best running shoes for flat feet` | 相关词过滤规则 |
| 停用词 | 本扩展未使用停用词表；空词、重复词会在解析时丢弃。 | — | 解析规则 |

### 有效新词的精确判定

1. 时间线至少 10 个点，否则不产生有效新词。
2. 该关键词序列的前 2 个点都为 0。
3. 最后 3 个点单调不下降（允许相等）。
4. 末点 ÷ 基准词末点 × 100 ≥ 阈值。
5. 基准词末点为 0 时：新词末点 > 0 视为通过百分比条件；两者都为 0 则不通过。
6. 通过后记录关键词、百分比、末点值；百分比为无穷大时界面不显示百分比徽标。

## 3. 词库状态：历史、收藏、词根

| 术语 | 定义 | 判定 / 字段 | 出现位置 |
| --- | --- | --- | --- |
| 历史词 | 至少被分析过一次的关键词。 | `count > 0` | 词库“历史”筛选、页面角标数字 |
| 收藏词 | 手动标记为收藏的关键词。 | `favorite: true` | 词库“收藏”、页面 ★ |
| 词根词 | 手动或批量标记为词根的关键词。 | `root: true` | 词库“词根”、页面“根” |
| 已分析次数 | 该关键词被打开/分析并累加的次数。 | `count` | 词库行、CSV |
| 最近使用 | 最后一次分析的日期。 | `lastUsed` | 词库行、CSV |
| 首次记录 | 第一次入库的日期。 | `firstSeen` | CSV 导出 |
| 关键词状态标记 | Trends 页面注入的小角标：★ 收藏、根 词根、数字 已分析次数。 | — | 页面注入 |
| 未分析 | 已在词库、但 `count = 0` 的关键词。 | `count = 0` | 词库行“未分析” |

## 4. 操作术语

| 术语 | 定义 | 说明 |
| --- | --- | --- |
| 去重 | 组内和组间按 `keywordKey` 去重；大小写、引号、多余空格不影响判定。 | `Running Shoes` 与 `"running shoes"` 视为同一个词 |
| 排序 | 组内关键词按中文/英文混合排序，组之间也排序。 | 不改变词本身 |
| 整理 | 连字符/下划线转空格、去掉 `.html`、压缩空格、去重、去空行。 | 来自 Trends Radar 的预处理 |
| 加引号 / 去引号 | 给关键词包上或去掉英文双引号；引号会进入 Trends 的 `q` 参数，用于短语匹配。 | 词库判定时引号会被忽略 |
| 对比 | 把某个词加入第一组关键词后一起打开 Trends；第一组已满 5 个时新建一组。 | 词库行“对比” |
| 批量分析 | 把词库里选中的关键词按 5 个一组切分，打开最多“最大打开组数”个标签页。 | 词库批量操作 |
| 分析全部 | 把工作台当前所有关键词组按设置打开；受“最多打开组数”限制。 | 工作台主按钮 |
| 最大打开组数 | 一次批量分析最多打开多少个 Trends 标签页；默认 10，可设 1–20。 | 设置 |
| 单组上限 | 一组最多 5 个关键词，来自 Google Trends 一次最多对比 5 个词的限制。 | 超出部分不参与该组分析 |
| 关键词评分 | TrendsBar 的旧功能，请求第三方 `s.trendsbar.net` 打分；合并版已移除。 | 不要与“有效新词”混淆 |
| 语义分析 | TrendsBar 的旧页签名，实际是“对比词 + 历史/收藏 + 外部分析入口”，不是 NLP 语义分析；合并版不再使用该名称。 | 相关能力已并入工作台与相关词 |
| 分析助手 | TrendsBar 的旧功能：Google、Time、Geo、Bing、Domains、Ahrefs 等外部分析链接模板。 | 合并版用“查”面板替代 |

## 5. 易混淆对照

| 容易混淆 | 区别 |
| --- | --- |
| 关键词 vs 关键词组 | 关键词是一个词；关键词组是多个词组成的对比集合，对应一个 Trends 页面。 |
| 关键词组 vs 词库 | 关键词组是当前工作区，会被分析、改写、删除；词库是长期存储，保存所有记录与状态。 |
| 种子词 vs 词根 | 种子词是这一轮挖词的起点；词根是可复用的模板/后缀词，可以作为种子，也可以只存在词库里。 |
| 相关词 vs 有效新词 | 相关词是 Trends 返回的候选；有效新词是其中通过时间线与阈值判定的子集。 |
| 对比基准词 vs 对比组 | 基准词是挖词算法里的固定分母；对比组是手动分析时第一组关键词的角色。 |
| 历史词 vs 收藏词 | 历史看“是否分析过”（count>0）；收藏看“是否手动标记”（favorite）。两者可以同时成立。 |
| 已处理 vs 相关词数 | 已处理数的是种子词；相关词数是发现的相关词，不参与最大词数的计数。 |
| 引号关键词 vs 普通关键词 | 引号只影响发送给 Trends 的查询写法；词库去重时忽略引号，视为同一个词。 |
| 词根 vs 语言学词根 | 本扩展的“词根”是运营用的模板词/后缀词，不是 morphology 里的词根词缀。 |
| 关键词评分 vs 有效新词 | 评分是已移除的第三方打分；有效新词是本地算法基于 Trends 时间线算出的结果。 |
| 搜索量 / 竞争度 / 难度 | 本扩展不提供这些指标；“查”面板只是打开 Ahrefs 等外部页面，数据不在本地计算。 |

## 6. 未作为独立概念使用的词

以下词在 SEO 里常见，但本扩展没有作为独立功能或字段使用：

- **长尾词**：没有单独分类，只在相关词过滤里限制不超过 6 个单词。
- **停用词**：没有停用词表；空词和重复词在解析阶段丢弃。
- **竞品词**：没有竞品词库或竞品分析；可以用基准词或手动分组模拟。
- **搜索量 / 竞争度 / 关键词难度**：不本地计算；“查”面板打开 Ahrefs 等外部页面。
- **关键词评分**：TrendsBar 的第三方评分功能，合并版已移除。

## 8. 相关文件

- `shared.js`：关键词解析、去重、引号、种子解析、词根与对比词预设。
- `sidepanel.js`：关键词组、词库、挖词页的界面与操作。
- `radar.js`：相关词提取、有效新词判定。
- `background.js`：挖词队列、批次、暂停/继续、词库收藏写入。
