# 合并后各部分的联动关系

两个扩展合并后，真正的联动来自三层：

1. **统一存储**：关键词、设置、词库、挖词状态都放在 `chrome.storage.local`，不再各存一套。
2. **统一入口**：所有打开 Trends 的动作都走同一个 `buildTrendsUrl`；所有页面注入都走同一套 `ensureTools` / `ensureBadges`。
3. **事件驱动**：侧边栏、内容脚本、后台都监听 `storage.onChanged`，一处修改，其他位置自动刷新。

## 1. 总览

```
                    ┌──────────────────────────────────────────┐
                    │           chrome.storage.local           │
                    │ settings / input / library / radar /     │
                    │ radarSeeds / pending                     │
                    └───────▲──────────▲──────────▲───────────┘
                            │          │          │
              ┌─────────────┘          │          └─────────────┐
              │                        │                        │
     ┌────────┴────────┐      ┌────────┴────────┐      ┌────────┴────────┐
     │   侧边栏四页签   │      │ Trends 内容脚本 │      │  后台 Service   │
     │ 工作台/词库/挖词 │      │ 注入按钮/角标   │      │ 爬虫/菜单/收藏  │
     │ /设置            │      │                 │      │ /翻译/相关词    │
     └─────────────────┘      └─────────────────┘      └─────────────────┘
```

- 侧边栏：写 `settings` / `input` / `library` / `radarSeeds`，读 `radar`。
- 内容脚本：读 `settings` / `input` / `library`，通过消息写 `pending` / `library`。
- 后台：写 `library` / `radar` / `pending`，读 `settings` / `input`。

## 2. 存储键的读写关系

| 存储键 | 写入方 | 读取方 | 作用 |
| --- | --- | --- | --- |
| `settings` | 侧边栏 | 侧边栏、内容脚本、后台 | 时间、地区、打开方式、最大组数、注入开关、翻译、挖词默认参数 |
| `input` | 侧边栏 | 侧边栏、内容脚本、后台 | 工作台关键词组文本 |
| `library` | 侧边栏、后台 | 侧边栏、内容脚本 | 统一词库记录（收藏/词根/次数/时间） |
| `radar` | 后台 | 侧边栏 | 挖词状态、进度、相关词、有效新词、下一批时间 |
| `radarSeeds` | 侧边栏 | 侧边栏 | 挖词种子文本框的持久化 |
| `pending` | 后台、内容脚本 | 侧边栏 | 一次性待处理关键词（右键/页面“分析”） |

## 3. 功能之间的联动

| 联动点 | 方向 | 触发 | 结果 |
| --- | --- | --- | --- |
| 时间/地区设置 | 设置 → 工作台 + 挖词页 + 页面注入 + 右键菜单 | 任一处修改 | 所有打开的 Trends URL 使用同一条件；挖词启动时快照当时条件 |
| 关键词输入 | 工作台 → 页面注入“对比” + 右键“对比” + 挖词“从输入框导入” | 编辑输入框 | 第一组关键词成为页面/右键对比的基准 |
| 词库 → 工作台 | 词库“加入”“对比”“批量分析” | 点击操作 | 追加到输入框、加入第一组、或按 5 个一组打开 |
| 工作台/单词分析 → 词库 | 工作台“分析全部”、词按钮、批量分析 | 打开 Trends | `count` 累加、`lastUsed` 更新，词库和页面角标同步 |
| 词库 → 页面注入 | 收藏/词根/次数 | 修改词库 | 页面角标 ★ / 根 / 数字实时刷新 |
| 页面“收藏” → 词库 | 内容脚本 → 后台 → `library` | 点击“藏” | 新建或更新记录，收藏标记为 true |
| 页面“分析” → 工作台 | 内容脚本 → `pending` → 侧边栏 | 点击“析” | 关键词自动追加到工作台输入框 |
| 右键“分析选中词” → 工作台 | 后台 → `pending` → 侧边栏 | 右键菜单 | 同上 |
| 右键“与对比组打开” | 后台读 `input` + `settings` | 右键菜单 | 第一组关键词 + 选中词打开 Trends |
| 挖词 → 工作台 | 挖词“加入输入框” | 点击 | 有效新词逐行追加到 `input` |
| 挖词 → 词库 | 挖词“加入词库” | 点击 | 有效新词写入 `library`，`count = 0` |
| 输入框/词库 → 挖词 | 挖词“从输入框导入”“从词库导入” | 点击 | 一次性复制为种子，之后不再自动同步 |
| 内置词根 → 词库/挖词 | 设置“导入内置词根”、挖词“内置词根” | 点击 | 词库得到 `root: true` 记录，或种子框追加 50 个词 |
| 最大打开组数 | 设置 → 工作台“分析全部” + 词库“批量分析” | 修改设置 | 限制一次打开的标签页数量 |
| 翻译目标语言 | 设置 → 每组“翻译” | 修改设置 | 决定翻译请求的目标语言 |
| 注入开关 | 设置 → 内容脚本 | 修改设置 | 控制快捷按钮、词库角标显示/隐藏 |
| 数据导入导出 | 设置 ↔ `settings` / `input` / `library` | 按钮 | 只覆盖这三项，不含挖词状态与种子 |

## 4. 实时联动、快照复制、未联动

### 实时联动

- `settings`：侧边栏修改后，内容脚本的注入开关、所有 URL 条件立即变化。
- `input`：工作台修改后，页面“对比”、右键“对比”、挖词导入读取最新内容。
- `library`：词库增删改后，侧边栏列表、页面角标、收藏状态立即刷新。
- `radar`：后台每次状态变化写存储，挖词页统计、进度、有效词列表实时更新。
- `radarSeeds`：种子文本框修改后持久化，重新打开侧边栏仍在。

### 快照 / 一次性复制

- 挖词启动时把 `dateRange` / `geo` / `benchmark` / `maxKeywords` / `threshold` 复制进后台状态；运行中再改设置不影响当前这一轮。
- “从输入框导入”“从词库导入”“内置词根”都是一次性追加，之后输入框或词库变化不会自动同步到种子。
- “加入输入框”“加入词库”也是一次性写入，挖词结果和词库之间没有反向引用。
- 页面“对比”、右键“对比”在点击那一刻读取 `input` 的第一组，之后不再跟随。
- 词库“对比”修改的是 `input`，不是页面正在打开的 Trends URL。

### 未联动 / 现有缺口

- **导出不含挖词**：`exportPayload()` 只导出 `settings` / `input` / `library`，不包含 `radar` / `radarSeeds`。
- **恢复默认不清理挖词**：`resetAll()` 删除 `settings` / `input` / `library` / `pending`，保留 `radar` 和 `radarSeeds`。
- **挖词结果入库后没有角标**：有效新词写入词库时 `count = 0`、`favorite = false`、`root = false`，页面角标不会显示，直到被分析或收藏。
- **打开方式不影响批量分析**：`openMode`（全部/只第一组）只作用于工作台“分析全部”，词库“批量分析”始终按 `maxTabs` 打开。
- **基准词只服务挖词**：`radarCompare` 不会自动加到手动分组或页面“对比”里。
- **最大组数不约束挖词**：挖词用“最大词数”，不是“最大打开组数”。
- **Trends 语言不影响挖词**：挖词 URL 固定 `hl=en-US`，手动分析才用 `settings.hl`。

## 5. 三条典型联动链路

### 5.1 在 Trends 页面点“收藏”

1. 内容脚本读取当前关键词。
2. 发送 `wf:favorite` 给后台。
3. 后台读 `library`，按 `keywordKey` 查找或新建记录，`favorite = true`。
4. 写回 `library`。
5. 侧边栏收到 `storage.onChanged`，词库列表刷新。
6. 内容脚本收到 `storage.onChanged`，重新扫描并显示 ★ 角标。

### 5.2 在词库点“批量分析”

1. 侧边栏取出选中的词库记录。
2. 按 5 个一组切分，受 `settings.maxTabs` 限制。
3. 每组调用同一个 `buildTrendsUrl`，读取当前 `settings` 的时间/地区/语言。
4. 打开标签页，调用 `touchKeywords` 累加 `count`、更新 `lastUsed`。
5. 写回 `library`。
6. 词库行、工作台关键词角标、页面注入角标同步更新。

### 5.3 挖词一轮

1. 挖词页把种子、基准词、阈值、最大词数发给后台。
2. 后台快照设置，创建后台标签页，逐批导航 Trends。
3. `webRequest` 拦截 `relatedsearches` / `multiline`，解析后计算有效新词。
4. 每批结束写 `radar`：已处理、相关词、有效新词、下一批时间。
5. 侧边栏监听 `radar`，更新统计、进度条、有效词列表。
6. 点“加入输入框/词库”后写入 `input` / `library`，工作台与词库立即可见。

## 6. 设计上的联动原则

1. **单一事实来源**：关键词状态只在 `library` 里维护，不再有独立的历史/收藏/词根列表。
2. **单一 URL 入口**：工作台、词库、右键、页面、挖词都调用 `buildTrendsUrl`。
3. **单一注入管线**：页面按钮和角标由一个 `ensureTools` / `ensureBadges` 统一管理。
4. **单向数据流**：页面/后台写存储，侧边栏消费；侧边栏写设置/输入/词库，其他端监听。
5. **实时优先，快照其次**：能监听存储的就实时联动；挖词这种长任务用启动时快照，避免运行中被配置变化打断。
